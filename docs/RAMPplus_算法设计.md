# RAMP+：多级聚合与官方反馈联合优化

## 定位与接口

RAMP+ 以 `RAMPDAG` 为基础，实现在 `src/ramp_plus.py`。输入为计算 DAG、核心数、DDR 带宽、Task 等待和 L1/UB 容量；输出为多个合法候选 Task 分区与分核计划。初始排程后可依据用户本地评估器产生的时间线生成 split/merge/move/reorder 邻域。

## 候选产生与排序

1. 继承 RAMP 的多种粗化配置与自然模块层级。额外生成随核心数变化的工作量均衡候选，避免局部两两合并收益非正时搜索停在初始 Task 粒度。这些是候选层级，不是按 case 编号指定最终答案。
2. 每个候选保留完整原 Op 归属，检查分区和商 DAG。按 Tensor 消费 Task 数计入共享数据搬运；原始依赖决定可聚合与跨核等待，Pipe cycles 决定工作量。官方 Step1 顺序的 L1/UB 活跃峰值给出溢出风险，调整代理排序；高风险候选仍可进入官方评估。
3. 对排序前若干计划运行官方问题一评估器。官方 Step2、Step3 的 Makespan、Spill、COPY 和逐核时间线是最终依据，代理分数只控制评估预算。

## 官方反馈邻域

从官方最长核心的末尾 Task 与最长 Task、以及高风险 Task 中选择 split 目标；先沿自然模块边界按工作量切，若 Task 只含一个模块则沿 Op 拓扑切。对中间 Tensor 边界较大的相依 Task 尝试 merge；对最长核心 Task 尝试 move 到其它核心，并尝试末尾相邻 Task reorder。每个候选再通过原 DAG 分区检查、商图检查和固定调度顺序检查，非法方案不会送官方。候选按 Step1 内存风险与时间代理排序后，在预算内官方复核。

每个被评估的邻居可记录操作、代理估计、Makespan、Task 数、Spill 与新增 COPY，以及是否接受。未改善的邻居也可用于分析代理误判或候选空间不足。

## 合法性、复杂度与预算

粗化每层只产生有界候选对，依赖连通性和商 DAG 无环是硬约束。每个邻居验证 Op 唯一归属、商图和核顺序；最终以官方校验为准。设模块数 M、Op/边数 V/E、粗化层数 L、保留候选数 K、邻居数 H，结构处理量近似 O(L·M log M + (K+H)(V+E))，另加每次 Task 内 Step1 预测与官方评估成本。运行器用候选数和时间预算限制评估，检查点支持 `--resume`。

## 已知局限

粗化候选、反馈轮数和 Step1 风险代理仍可能漏掉更好方案；搬运、Spill 与 Makespan 之间也存在取舍。具体性能应在用户持有的官方附件上重新评估。
