# V2+：结构驱动的两级聚合

## 定位与接口

V2+ 使用 V1/V2 的自然模块作为候选基础。输入为 `GraphModel`、自然计算模块、核心数和硬件配置；输出为合法 Task 分区及一次确定性的多核计划。实现见 `src/aggregate_v2plus.py`，三路线调用入口见 `scripts/run_all_problems.py`。核心策略仍是先定 Task，再调用 `make_plan` 分核。

## 规则

1. 从原 DAG 提取模块依赖、Op/Pipe cycles、Tensor 生产者和消费者。共享 Tensor 按消费它的**不同 Task 数**收费，同一 Task 多次读取视为复用。对共享中间 Tensor 同时检查生产 Task 和消费 Task，不能把 fan-out 展开成普通边求和。
2. 核心数决定候选 Task 数序列。针对每个粒度构造 Pipe 工作量均衡、Tensor 亲和、拓扑连续三类分组。各类均检查原 Op 唯一归属和 Task 商图无环；失败候选舍弃。只有一个自然模块时，额外给出按 Op 拓扑与工作量切开的候选。
3. 对候选先执行确定性多核排程，再估计关键完成时间、分区新增 COPY 和每个 Task 的内存风险。内存风险按 Tensor 首次/最后一次使用计算 L1、UB 峰值，优先以官方 Step1 的 Task 内 Op 顺序估计；不能取得该顺序时回退原图拓扑顺序。风险只排序，不是非法判定。
4. 按时间代理、搬运和潜在 Spill 排序。运行器在预算内将候选送用户本地的官方评估器，以官方结果选择方案。

规则不读取 case 名称或编号。`--cases` 只决定实验样本。候选枚举、同分排序、分核均有确定性键。

## 合法性与复杂度

每个候选展开自然模块后，使用 `validate_partition` 检查 Op 唯一归属与商图无环；排程及官方问题一评估进一步检查核顺序。Op 拓扑连续切分使单自然模块拆分仍无环。若一个 Task 合并了多条依赖路径，商图环检查可拒绝非凸聚合。

设自然模块数为 M、Op 数为 V、边数为 E、候选粒度数为 K。候选构造约为 O(KM log M)，每个候选的商图/边界检查约为 O(V+E)，Task 内 Step1 风险估计需扫描对应 Op/Tensor，整体上界取决于官方 Step1 调度过程。V2+ 不进行多轮邻域搜索。

## DAG 来源与硬件来源

自然模块、依赖、共享 Tensor、Pipe 类型及 cycles 来自原始计算图。候选 Task 数与核心数、Pipe 工作量、DDR 带宽、Task 等待、L1/UB 容量来自问题一硬件模型。`memory_risk.py` 共用预测器仅影响排序，不改变官方合法性标准。

## 已知边界

当前对“整个图只有一个自然模块”的大模块有显式 Op 级切分；在多个自然模块中夹杂一个异常大模块时，候选集仍可能不足。纯分区先行方式也无法利用官方时间线对核心尾部 Task 再迁移。Step1 顺序估计省略边界 COPY，属于风险代理，最终 Spill 以官方 Step2 为准。
